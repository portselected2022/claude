## 零、一页结论

**一句话：你不是新手。你卡在"单点工匠"这一级：研报这条工作流做得很精，但验证没有被强制、经验没有复利、系统不会自己启动、成品没有接到变现。高手和新手的差别不在提示词，在这四层。**

### 九个判断

1. **大家用 agent 解决什么。** 写代码仍是第一用途，但正在外溢。Claude Code 里修 bug 的会话占比从 33% 降到 19%，操作软件、写作和数据分析在涨 [A1-S5]。"整件交出去"发生在 agent 产品里：同样写一篇博客，聊天里中位要来回 13 轮，Claude Code 里只要 1 次提示 [A1-S1]。真实落地集中在两处：软件工程（约占 agent 工具调用的一半）和后台固定流程 [A1-S6][A1-S2]。
2. **多 agent 不是越多越好。** 它只在"宽、可并行、有校验"的任务上占优：Anthropic 的研究系统比单 agent 高 90.2%，但 token 约为普通聊天的 15 倍 [A1-S7]。在顺序任务上，多 agent 反而下降 39%–70% [A1-S12]。小团队的默认做法是"单 agent + 固定工作流 + 自动校验"，多 agent 只用在广度研究和独立评审上。
3. **最大的一跳在新手 → 中级。** 中级及以上的严格成功率（28–33%）约为新手（15%）的两倍，遇到麻烦时的放弃率从 19% 降到 5–7%；从中级到专家差距不大 [A2-S2]。这些是相关关系，不是因果。再往上的提升，主要靠 harness 和异步运行，而不是提示词（推断）。
4. **高手只做三件事。** 把 Claude 看不到的信息交给它；给它一个能跑出通过或失败的检查；把零例外的规则交给 hook 和 deny 规则强制执行 [A2-S1]。人不盯过程，只守三个点：开始、定义完成、签发。
5. **黑客松里，领域知识是决定性因素之一。** Opus 4.6 场 5 位获奖者里 4 位不是职业开发者，冠军是一名律师；4.7 场的获奖者里，既有医生转行的工程师、自学电子维修的创业者，也有职业开发者 [A3-S1][A3-S2]（厂商自报）。强队赢在四件事：把领域知识写进 skill 和参考文件、规格先行、按"所有权"并行、用 10–12 个案例的小评测验收。有一个项目只加了一个知识文件，准确率就从 74% 升到 81% [A3-S2]。
6. **企业真正上线的，都是结果能验证的环节。** 内部编码、数据审阅、全员办公已上生产；合规、会计、端到端出研究结论仍在试点（高盛到 2026 年 2 月仍称"早期"）[A4-S3]。拉开差距的是交付纪律：基线、评测、最小权限、人工闸门、打包分发、度量 [A4]。
7. **小团队的人效差距是真的，"一人独角兽"还不是。** Gamma 约 50 人、年化经常性收入 1 亿美元，但高人效公司大多卖的就是 AI 产品；"一人十亿美元公司"至今没有经核实的实例 [A5]。可复制的模式是：一个人当 agent 管理者，机器能验证的环节交给定时 agent，发布和涉钱涉法的环节留给人，每周把错误写回规则 [A5]。
8. **最大的风险是错觉和失控。** 资深开发者用 AI 实际慢了 19%，却自认为快了 20% [A2-S13]。AI 会放大团队原有的长处和短处 [A4-S10]。研报 PDF 属于不可信输入，你的行情工具又带发帖能力，两者凑在一起就是提示注入的风险组合 [A4-S17]。
9. **你下一步该补的是四层，不是技巧。** 强制层、复利层、自动启动层、交付层，见第八章。

## 一、大家用 agent 到底在解决什么

### 1.1 五个事实

**第一，写代码仍是第一用途，但份额在被稀释，并在往 agent 产品里迁。** Claude.ai 上"计算机与数学"类任务的占比，从 2025 年 3 月峰值的 40% 降到 11 月的 34%；同期 API 上这一类从 44% 升到 46% [A1-S2]。Claude Code 内部的变化更明显：2025 年 10 月到 2026 年 4 月，修 bug 的会话占比从 33% 降到 19%，操作软件（装依赖、配环境、跑脚本）从 14% 升到 21%，写作与数据分析合计从约 10% 升到约 20% [A1-S5]。也就是说，Claude Code 正在从"写代码的工具"变成"在电脑上办事的工具"。

**第二，"整件交出去"发生在 agent 产品里，不在聊天框里。** 同样是写一篇博客文章，在聊天或 Cowork 里中位要来回 13 轮，在 Claude Code 里只要 1 次人工提示；31 类产出里，有 26 类在 Claude Code 上的自主度更高 [A1-S1]。Claude Code 单轮最长运行时间（第 99.9 百分位）从不到 25 分钟升到 45 分钟以上 [A1-S6]。

**第三，真实落地集中在两处：软件工程和后台流程。** Anthropic 抽样了 99.8 万次公开 API 的工具调用，软件工程占近一半，商业智能、客服、销售、金融、电商各自只有几个百分点 [A1-S6]。API 上的非编码用途集中在邮件分类、发票处理、B2B 冷邮件这类固定流程 [A1-S2]。行业调查的方向一致：企业部门级 AI 支出的 55% 花在编码上 [A1-S15]；LangChain 的受访者把客服（26.5%）和研究与数据分析列为首要用例 [A1-S13]。

**第四，规模化仍是少数，人仍在环。** McKinsey 的调查里，23% 的企业已在某处规模化使用 agent，但任何单一职能里规模化的比例都不超过 10% [A1-S14]。Stack Overflow 2025 年的调查里，52% 的开发者不用 agent 或只用更简单的 AI 工具；用 agent 的人里，69% 认为提效了，只有 38% 认为代码质量提高了 [A1-S16]。

**第五，任务越长越不可靠。** API 上，1 小时以内的任务成功率约 60%，5 小时以上约 45%，约 3.5 小时处跌破 50% [A1-S2]。所以，把长任务切成 1 小时以内、每段都能检查的小段，是更稳的做法（推断）。

### 1.2 用途地图

| 方向 | 典型任务 | 证据强度 | 适合的架构 | 成熟度 |
|---|---|---|---|---|
| 软件开发 | 写功能、修 bug、重构、测试 | 强 | 单 agent 为主；能切成独立模块时用多 agent | 已规模化 |
| 操作软件与环境 | 装依赖、配环境、跑脚本、运维 | 中 | 单 agent | 开发者群体内已规模化 |
| 广度研究与信息综合 | 多来源检索、横向对比、综述、核查 | 强 | 多 agent：主 agent 分派，子 agent 并行 | 产品功能已规模化；企业内多为试点 |
| 写作与内容生产 | 报告、文章、营销文案 | 中 | 单 agent + 模板和闸门 | 已规模化（有人审） |
| 数据分析与表格 | 清洗、统计、建表、看板 | 中 | 单 agent，人在环 | 试点→规模化 |
| 后台流程 | 邮件分类、发票处理、冷邮件 | 中 | 固定工作流（API 管道） | 企业 API 上已规模化 |
| 客服 | 问答、工单分流 | 中 | 工作流 + 单 agent，人工兜底 | 试点→局部规模化 |
| 金融专业工作流 | 纪要解析、模型更新、可比估值与 DCF、尽调数据包、研报初稿 | 弱（多为产品说明） | 单 agent + skill 或插件；广度阶段可用多 agent | 试点 |
| 评审与排错 | 多视角代码评审、竞争假设调试 | 中 | 多 agent（agent teams 或多个评审 subagent） | 试点（实验功能） |
| 大型并行工程 | 编译器、大规模迁移 | 弱（单个示范） | 多 agent + 近乎完美的自动测试 | 试点 |
| 无人值守的"全自主公司" | 自动接单、发布、互动 | 弱（多为反证） | — | 炒作为主 |

（证据强度和成熟度是 A1 的综合判断，依据见 `agents/A1_用途地图.md`。）

### 1.3 多 agent：什么时候有用，什么时候坏事

多 agent 的收益来自两件事：并行，以及多花 token。代价也在这两件事上。

- Anthropic 的研究系统（Opus 主 agent 带 Sonnet 子 agent）在内部评测上比单 agent 高 90.2%，但 token 消耗约为普通聊天的 15 倍；在 BrowseComp 上，token 用量单独就能解释 80% 的表现差异。Anthropic 明确说"大多数编码任务"不适合，因为要共享上下文、相互依赖多 [A1-S7]。
- Google 等机构对 180 种配置做了对照：在可并行的金融推理任务上，集中式协调提升 80.9%；在严格顺序的规划任务上，所有多 agent 变体都下降 39%–70%；各自独立并行的多 agent 会把错误放大 17.2 倍，集中式也有 4.4 倍 [A1-S12]（只读到摘要，原文域名在本环境被拦截）。
- 16 个 Claude 用两周、近 2,000 个会话、不到 2 万美元，写出约 10 万行 Rust 的 C 编译器，能编译可启动的 Linux 6.9。但遇到"编内核"这种单一大问题时，16 个 agent 撞上同一个 bug、互相覆盖修复，直到用 GCC 当对照把问题切小，才恢复并行 [A1-S10]。

据此可以写成一张判断表：

| 任务特征 | 选择 |
|---|---|
| 步骤和格式固定、每天重复、出错代价高 | 固定工作流：脚本或 skill 串起来，模型只做其中的判断步骤，结尾跑校验 |
| 广度优先、子问题互不依赖、材料超出一个上下文 | 多 agent：主 agent 分派，子 agent 并行，结果回收汇总 |
| 强顺序依赖、要共享全部上下文、多方改同一个产物 | 单 agent；subagent 只做查询和核对，不写产物 |
| 需要互相挑刺的评审、根因不明的排错 | 多个评审 subagent 或 agent teams，每个只看一个视角 |
| 能切成大量小任务，且有近乎完美的自动测试 | 多 agent 并行，用任务表认领 |
| 价值低的日常小事 | 单会话 |

**对你的含义：** "一份研报 → 一份中文精华"是单一产物、强顺序、要求风格统一的任务，正落在不适合多 agent 的区间，应继续由单 agent 按 v3 的闸门跑。多 agent 应该放在前置的"读材料"环节：同一主题的 3–5 份大行报告各派一个 subagent，按固定格式抽取（数字、页码、原句），再由主 agent 汇总比对。这恰好就是你"大行吵架"栏目的生产方式。

### 1.4 财经团队在用 agent 做什么

Anthropic 在 2025 年 7 月到 2026 年 2 月间推出了三层金融产品：数据连接器（S&P Capital IQ、PitchBook、LSEG、Moody's、FactSet、MSCI 等）；Claude for Excel 和 6 个预置的金融 Agent Skills（可比公司、DCF、尽调数据包、公司简介、业绩分析、首次覆盖报告）；Cowork 的角色插件（投行、股票研究、PE、财富管理）[A1-S17][A1-S18]。但公开的效果数据几乎都是厂商自报。Evident 指数覆盖的 50 家大银行里，只有 9 家披露了处于试点或生产阶段的 AI agent [A1-S19]。企业案例和交付方法见第五章。

## 二、你为什么觉得自己还在新手区：对照仓库的诊断

**结论：你不是新手。你卡在"单点工匠"这一级：有一条工作流做得很精，但它还没有变成一个会自己运转、越用越强的系统。**

继续把提示词写得更好，对你帮助不大。Anthropic 分析了约 23.5 万人的约 40 万个 Claude Code 会话，发现能力提升主要发生在"新手 → 中级"这一步，从中级到专家差距不大 [A2-S2]。这项研究判断专长看三个信号：指令框定得是否精确、是否要求 Claude 验证、由谁纠正谁。按这三个信号，你大概率已经在中级以上（推断：你的会话没有被这项研究分类过）。你觉得"没有大的提升"是真实的感受，原因不在会不会用，而在你的用法已经到了"对话式"的天花板。

**定级：L2 已完成，L3 做了一半** [A2]（阶梯见第三章）。验证脚本你已经有了，但它们还没有被强制执行，也没有跟着你走到每一个干活的地方。

### 2.2 七个卡点（每条都能在仓库里找到证据）

**卡点 1：护栏能不能生效，取决于你在哪个目录开会话；红线全靠模型记得。**

先看两次事故。SKILL.md 记录：8 月 28 日和 9 月 1 日两次"都是因为没读护栏才退化成翻译"。`环境与已知坑.md` 写清了根因："两次事故都是在别的目录开的会话，护栏根本没机会加载"，因为项目级的 skill 只在那个目录里生效。

再看红线。不荐股、不发原文、平台版去二维码，都只写在提示词和手册里。仓库里没有一个 hook，也没有一条 deny 规则。官方最佳实践把指令分成两类 [A2-S1]：

- **写给模型看的**（提示词、CLAUDE.md、skill）：遵不遵守由 Claude 自己决定，"通常会照做"，但没有保证；
- **由 Claude Code 执行的**（hook、deny 规则）：每次都会执行。

教训有两条。第一，护栏必须跟着你走：装在用户级，或者打包成插件，而不是只放在某个项目目录里。第二，零例外的客观红线要交给 hook 和 deny 规则。

还要注意一点：研报的主力生产在 Windows 和 Mac 两台本机的工程目录里，不在这个仓库。所以强制层也要配在用户级或插件里，只放在本仓库 `.claude/settings.json` 的规则管不到那两个目录。

**卡点 2：skill 靠复制分发，教训沉淀不到同一个地方。**

v3 的 SKILL.md 和环境说明里写着：用 `cp -R` 和 `xcopy` 把 skill 复制到两台机器的用户级目录；这个仓库和云端的 `setup.sh` 里又各有一份。SKILL.md 开头专门提醒"9.01 用的就是第三份拷贝"。拷贝一多，你在哪台机器上改了规则，规则就只活在那一份里。

（历史产出里，二维码和字体各有 22 份完全相同的副本，都早于 v3，属于遗留问题。v3 已经改为从一处引用母本。）

高手的做法正好相反：Boris Cherny 的团队共用一份 CLAUDE.md，Claude 每犯一次错就写进去，每周更新好几次 [A2-S4]；Every 的"复利工程"要求每完成一件事，都让下一件更容易 [A2-S17]。

**卡点 3：你是唯一的启动按钮。** 仓库里没有任何定时或事件触发的配置：没有 `.claude/settings.json`，没有 GitHub Actions，没有定时任务。每一份产出都要你开一个会话、说一句话才开始，所以产出和你在线的小时数成正比。这还是"人加工具"，不是"系统"。官方文档的说法是：Claude 能把一件长任务自己做完，唯一做不到的是自己决定开始 [A2-S1]。

**卡点 4：CLAUDE.md 写的是 Claude 自己看得见的东西。** 你的 CLAUDE.md 是一张目录表，加上归档约定和知识库的读取路由。2026 版官方最佳实践在"可以停掉的旧做法"里，专门列了"在 CLAUDE.md 里描述架构和文件布局"，因为 Claude 会自己读仓库 [A2-S1]。该删的只是目录表；归档约定和读取路由是读代码看不出来的决定，要保留。还该补上它看不见的东西：怎么验证、哪里会误导、被纠正过两次的事。

**卡点 5：产出不等于交付。** 10-19 那份研究的 Markdown 终稿约 27 万字符（其中汉字约 8 万）。它要服务哪个决定，谁会读完？高手会先定"谁看、看完做什么决定"，再定长度上限。你要求社群消息"越短越好"，对自己的研究报告也该用同一条标准。

**卡点 6：多 Agent 规模过大，撞上了配额。** 那一轮 12 个 Agent 并行检索，耗尽了共享检索配额，又三次撞上平台用量上限（见那份报告的研究进度记录）。这次 6 个 Agent 也在途中一起撞上了 5 小时用量上限。多 Agent 适合"宽而且彼此独立"的任务，研究正是这类任务，但代价是 token 成倍增加：Anthropic 自己的多 Agent 研究系统，消耗约为普通聊天的 15 倍 [A1-S7]。3–5 个 Agent 加一个独立核验者，通常比 12 个 Agent 跑四轮更划算（推断）。

**卡点 7：最强的资产没有接到分发和变现。** 研报 skill 的终点是 A4 PDF。10-18 的手册写着"需要加一个小红书卡片版导出模式"，仓库里还没有。从 PDF 到群里每天 08:00 的观点卡、再到付费合集，中间全是手工。另外，现有精华的末页都印着微信二维码，按平台规则，不能直接发进小红书、抖音的任何位置，包括付费群。最后一公里没有自动化、也没有合规版本，前面的精度就变不成收入。

### 2.3 一句话诊断

> 你现在的 Claude 是"对话式、一次性、靠你启动、做完即止"；高手的 Claude 是"系统式、可复利、定时或事件启动、验证通过才算完、交付到用户手里才算完"。

下一步不是学更多技巧，而是给已有的工作流补上四层：

1. **强制层**：放在用户级或插件里的 hook 和 deny 规则，跟着你走到两台机器和云端；
2. **复利层**：skill 只留一个来源，每次纠正都写回去；
3. **自动启动层**：定时任务；
4. **交付层**：平台合规的卡片版导出，接上社群。

第八章给出 30 天的做法。

**进步要用数字衡量，不能凭感觉。** METR 的随机对照实验里，资深开发者用 AI 实际慢了 19%，事后却自认为快了 20% [A2-S13]。建议每份成品记三个数：第一次就通过 verify 的比例、被你打回的轮数、从拿到研报到发布用了多久 [A2][A4]。

## 三、高手怎么用：三个杠杆、八张工作流卡片、L0–L5 阶梯

### 3.1 三个杠杆

官方 2026 版最佳实践把高手和新手的差别归结为三件看得见的事 [A2-S1]：

1. **把 Claude 看不到的信息交给它。** 会议上做的决定、只存在某个人脑子里的流程、"完成"到底指什么。
2. **给它一个能跑出通过或失败的检查。** 测试、构建的退出码、脚本对照、截图。再要求它拿出证据：跑了什么命令、输出是什么。一句"测试都过了"说明不了什么。Boris Cherny 自述，有了验证回路，最终质量能提升 2–3 倍 [A2-S4]（自述，未经第三方核实）。
3. **把不能有例外的规则交给 harness。** 一行规则加粗之后还被忽略，就说明它该改成 hook 或 deny 规则。

独立研究指向同一方向。UCSD 做了 13 场现场观察，又调查了 99 名资深开发者，结论是职业开发者不 vibe：他们先规划，再监督，并验证 agent 的全部产出 [A2-S12]。HumanLayer 的 Dex Horthy 说：计划里错一行，会变成几百行坏代码；调研里错一行，会变成几千行 [A2-S9]。所以高手把人工把关前移到调研和计划阶段。

### 3.2 新手和高手的可观测差别

| 观察点 | 新手 | 中级及以上 |
|---|---|---|
| 每条提示触发的动作 | 约 5 个 | 约 12 个（专家） |
| 每条提示的产出 | 约 600 词 | 约 3,200 词（专家） |
| 严格口径的"已验证成功" | 15% | 28–33% |
| 至少部分成功 | 77% | 91–92% |
| 遇到麻烦时放弃 | 19% | 5–7% |
| 怎么下指令 | 泛泛而谈 | 带着对代码库和环境的具体了解 |
| 怎么验证 | 不提，或只问一句"好了吗" | 说清验证什么，要命令输出或截图 |

来源：[A2-S2]，厂商自报。专长等级和成功与否都由模型读会话记录判定，统计只含交互会话。稳妥的读法是：**中级及以上的严格成功率约为新手的两倍。** 这是相关，不是因果："要求 Claude 验证什么"本身就是判定专长的信号之一 [A2]。

一句话归纳：**高手先定义什么叫"完成"，再放手让它做；新手先放手，事后再猜它算不算完成。**

### 3.3 八张工作流卡片

| 是谁 | 核心做法 | 关键配置 | 效果（来源性质） |
|---|---|---|---|
| **Boris Cherny**（Claude Code 作者） | 终端并行开 5 个会话，网页端再开 5–10 个；多数会话先进 plan mode，计划定稿后一次做完；Claude 每犯一次错就写进团队共用的 CLAUDE.md | 斜杠命令（`/commit-push-pr` 每天用几十次）；code-simplifier、verify-app 两个 subagent；PostToolUse hook 自动格式化；用 `/permissions` 预先批准安全命令，不跳过权限 | 有验证回路，质量提升 2–3 倍（自述）[A2-S3][A2-S4] |
| **Anthropic 内部团队** | 非工程岗位也在用：增长营销批量生成广告变体，法务和数据科学家自己做工具 | 专职 subagent、GitHub Actions 自动评论 PR、自建 Figma 插件 | 数百条广告变体"几分钟而非几小时"（厂商自报）[A2-S5] |
| **Dex Horthy**（HumanLayer） | Research → Plan → Implement 三步走；每步的产物写成文件，下一步开新会话、从文件起步；人主要审调研和计划 | 调研和计划存进 `thoughts/` 目录；subagent 只管检索和压缩；上下文用量控制在 40%–60% | 30 万行的 Rust 项目上约 1 小时出修复 PR；也公开了一次 7 小时没做成的案例（自述）[A2-S9] |
| **Mitchell Hashimoto**（Ghostty 作者） | 先自己做一遍，再让 agent 背对背做一遍对照；每天最后 30 分钟启动"收工 agent"；每次失败都改环境 | engineer the harness：让同样的错不再出现 | 没有量化（自述）[A2-S6] |
| **Every / Kieran Klaassen** | "复利工程"：计划 → 执行 → 评审 → 沉淀 | 开源插件 compound-engineering | 5 个产品基本都由单人工程团队维护（自述）[A2-S17] |
| **Geoffrey Huntley**（Ralph 循环） | 把同一份 PROMPT.md 反复喂给 agent；进度存在文件和测试里，不靠对话记忆 | `while :; do cat PROMPT.md \| claude ; done`；官方插件改用 Stop hook 拦住退出 | 本人强调这是要有人盯着的技巧 [A2-S11] |
| **Steve Yegge**（Gas Town） | 把开发者分成 8 个阶段；到第 7–8 阶段同时管几十个 agent，并自建编排器 | Gas Town 编排器 | 作者本人说只适合第 7–8 阶段的用户 [A2-S7] |
| **Anthropic 工程团队**（长任务 harness） | 初始化 agent 先写功能清单、进度文件和启动脚本；之后每个会话只做一个功能，测试通过才标"已通过" | 200 多条功能清单一开始全部标为未通过；`claude-progress.txt`；浏览器端到端测试 | 点名了两种典型失败：想一次做完；看到进展就宣布完工（厂商自报）[A2-S10] |

八张卡片的共同点只有一个：**人不再盯过程，而是守住三个点：开始、定义完成、签发。**

### 3.4 进阶阶梯 L0–L5

| 级别 | 典型行为 | 关键配置 | 常见卡点 | 升级的验收标准 |
|---|---|---|---|---|
| **L0** 聊天加复制粘贴 | 在网页聊天里要代码或文案，手动贴进文件 | 无 | 每次重新交代背景 | 连续 5 个小任务，都由 Claude 直接在项目里读写、跑命令完成 |
| **L1** 单会话 vibe coding | 一个会话从头聊到尾，看着差不多就收工 | 默认设置 | 一个会话塞几件事；同一处纠正三四次 | 开工前写下完成标准；纠正两次还不对就 `/clear`、重写提示；收工时拿得出证据 |
| **L2** 上下文工程 | 先让 Claude 采访自己，写出 SPEC.md；plan mode 定计划；一个任务一个会话 | 短 CLAUDE.md（200 行以内）、`.claude/rules/`、skill | CLAUDE.md 越写越长；闸门只写成文字，偶尔被跳过 | 新会话光读文件就能开工；CLAUDE.md 每一行都过得了"读代码看不出来"这一关 |
| **L3** 验证闭环加可复用资产 | 每个任务都有能跑的检查；没有例外的规则交给 hook；diff 由没参与编写的 reviewer 审 | Stop hook、PreToolUse hook、deny 规则、只读 reviewer subagent、`/code-review`、回归样例集 | 检查要靠 Claude 自觉去跑；把偏好也写成 hook | 交付物 100% 过机器检查，而且由 hook 保证；同类错误不出现第二次；新项目不复制任何东西 |
| **L4** 并行与异步 | 独立任务各开一个 worktree 或云端会话；`claude -p` 跑批量；`/loop` 盯 CI | `claude -w`、限定工具的自定义 subagent、`--allowedTools`、`--permission-mode dontAsk`、`--max-turns`、GitHub Actions | 把紧耦合任务硬拆开；人成了审阅瓶颈 | 同时推进 3 个以上独立任务；每个无人值守任务都答得上官方"5 问" |
| **L5** 系统化 | 定时 agent 每天自动产出；评测集量化质量；插件分发 skill 和 hook；复利工程 | `/schedule` 云端定时任务、agent teams（实验功能）、评测基线、插件市场、`/usage` | 成本失控；产出没人签收；编排器本身成了负担 | 定时任务连续 2 周无人干预仍合格；质量有基线数字，每周追踪 |

分级综合了 [A2-S1][A2-S2][A2-S6][A2-S7]，验收标准是 A2 的建议（推断）。**你在 L2 → L3 之间。**

官方的无人值守"5 问"是 [A2-S1]：

1. 它知道什么叫完成吗？
2. 它能检查自己的工作吗？
3. 它能碰什么？
4. 什么能让它停下？
5. 结果交给谁签收？

### 3.5 十一个反模式

| 反模式 | 证据 | 解法 |
|---|---|---|
| 一个会话什么都塞 | 每次请求都重发整段对话，三个无关任务攒在一起，做第四个时每轮都在为前三个付费 [A2-S1] | 任务之间 `/clear` |
| 纠正个没完，或原样重跑碰运气 | 同一处纠正两次还不对，第三次只会让对话里多一次失败记录 [A2-S1] | `/clear`，写一条吸收了教训的新提示；回到计划层修 |
| CLAUDE.md 过长、靠加粗强调 | 官方建议 200 行以内；HumanLayer 自家的根文件不到 60 行 [A2-S16] | 只写读代码看不出来的；没有例外的规则改成 hook |
| 没验证就收工 | 长任务实验里，agent 看到有进展就宣布完工 [A2-S10]；新手严格成功率只有 15% [A2-S2] | 给它能跑的检查，要证据；Stop hook 兜底 |
| 不看 diff，只看总结 | METR：自我感觉和实测相差约 39 个百分点 [A2-S13] | 要命令输出；让没参与编写的 reviewer 看 diff |
| MCP 和工具堆太多 | 已连接的 MCP 不用也占上下文 [A2-S1] | 在 `/mcp` 里关掉不用的 |
| 紧耦合的任务硬上多 agent | 两个队员改同一个文件会互相覆盖 [A2-S19] | 按文件划分谁负责什么；先拿调研和评审做并行 |
| 用文字指令保护生产环境 | Replit：用户下了"冻结"指令，agent 仍删了生产库 [A2-S14] | deny 规则在任何权限模式下都生效；环境隔离 |
| 成本失控 | 有用户让它 24 小时在后台跑，Anthropic 因此加了周限额 [A2-S18] | `--max-turns`、`--max-budget-usd`、`/usage`；简单活交给 Haiku |
| 把 harness 设计过度 | 规则多到 40 条时，大半是本可以让 Claude 自己权衡的偏好 [A2-S1] | 只给零例外的规则上 hook；评审提示里写"跳过风格问题" |
| 跳级上编排 | Gas Town 作者说它只适合第 7–8 阶段的用户 [A2-S7] | 先过 L3 验收，再谈 L4、L5 |

## 四、黑客松：领域知识是决定性因素之一

### 4.1 一个反直觉的事实

2026 年，Anthropic 和 Cerebral Valley 合办了两场 Claude Code 黑客松，获奖名单如下（均为厂商自报）：

- **Opus 4.6 场**：入选 500 人，第三方称约 1.3 万人申请。5 位获奖者里有 4 位不是职业开发者，冠军是一名人身伤害律师，自称"一行代码没写" [A3-S1][A3-S10]。
- **Opus 4.7 场**：冠军是医生转行的软件工程师；其他获奖者里有自学电子维修的创业者、教计算机的大学讲师，也有全栈开发者和工业软件工程师 [A3-S2]。明确不是程序员的只有 2 位。

两场都由 Anthropic 选人、评奖、发文。获奖项目解决的都是能用金额和时长量化的痛点，比如加州建房许可，首次提交被打回的比例超过 90%，平均要拖 6 个月 [A3-S1]。

强队的共同点不是"不会写代码"，而是**深懂某个领域**，并且把这份懂行写进了系统。**这对你是好消息：**你懂投行研报、懂读者、懂平台规则，这正是这些赢家手里的那张牌。

### 4.2 强队的六个做法

| 做法 | 例子 |
|---|---|
| **把领域知识写进 skill，而不是写进提示** | 冠军 CrossBeam 第一天就把州政府手册拆成 27 个参考文件，再加一个只做路由的 SKILL.md [A3-S4]。MaestrIA 把 17 条诊断规则、19 个基准价格写进一个知识文件，在 12 个真实案例、9 个维度的评测上，准确率从 74% 升到 81%，系统提示一字没改；标准答案由作者做木匠的父亲给出 [A3-S2] |
| **规格先行，计划交给另一个 agent 复审** | Maieutic 写代码前先用 2 天写规格；ARIA 第 2 天整天只排计划；CrossBeam 的 Agent SDK 计划写了 1,077 行，常交另一个 agent 复审 [A3-S2][A3-S4] |
| **按"所有权"并行** | Medkit 同时开 4 个会话，一个会话负责一个模块；Wrench Board 一个领域一个 agent，5–6 个同时跑。CrossBeam 的 subagent 出过"过度研究、互相踩踏、上下文爆掉"的问题，改成各写各的输出文件、由主 agent 读文件汇总后才稳定 [A3-S2][A3-S4] |
| **小评测和输出契约** | Medkit 的评分 agent 只能引用一份策展过的临床指南白名单，"防止编造来源" [A3-S7]。CrossBeam 吃过亏：输出是嵌套结构，解析器要的却是平铺数组，结果丢了数据 [A3-S4] |
| **把成本和取舍量化** | CrossBeam 每次云端运行花 1.46–8.69 美元；为了速度，放弃了准确率 95%、耗时 35 分钟的方案，选了准确率约 85%、耗时 10–15 分钟的方案 [A3-S4] |
| **赛前的脚手架本身就是资产** | 纽约场冠军把自己的 Claude Code 配置（模块化规则、9 个 subagent、hooks、skills）开源成 ECC，GitHub 显示约 30 万个 star（API 读数，数字异常高，未复核）[A3-S8][A3-S9]。他的经验是：每个项目只开当前要用的 MCP，开着的少于 10 个，工具总数少于 80 个 [A3-S8] |

评委看什么：公开的权重只有一项，Demo 占 30% [A3-S12]（只读到摘要）。从奖项设置看，评委奖励三件事：真实且可量化的痛点、能真跑的端到端闭环、对新能力的实质使用（推断）。

### 4.3 三样不能迁移

1. **演示不等于系统。** CrossBeam 给评委的演示回放的是预先算好的结果，根本没运行 agent。作者在提交前 45 分钟才发现，用 12 分钟、8 次提交补上了真跑模式 [A3-S4]。
2. **冲刺的节奏不能复制。** CrossBeam 的作者在最后约 30 小时里只睡了 6 小时 [A3-S4]。
3. **测试和合规只够演示。** 10 个获奖项目的公开描述里，只有 MaestrIA 写明做了防提示注入和限流 [A3-S2]。

转化也慢：CrossBeam 赛后约半年才拿到第一份市政协议（作者自述）[A3-S3]；一项 2020 年的研究发现，只有约 5% 的黑客松项目能持续 5 个月以上 [A3-S22]。

### 4.4 把黑客松那一周压成你的每周循环

1. **周一 30 分钟**：写一页周规格（选题、不做什么、交付物、红线检查项），交给另一个会话复审。
2. **周二到周四**：按"一份研报、一个会话、一个文件夹"并行 2–3 路，主会话只做汇总和终审。
3. **发布前**：Stop hook 自动跑红线扫描和 PDF 回查。
4. **周五**：写一页决策日志，更新知识文件，重跑评测集、记下分数。

**你的"Demo"是首图和前 3 秒。** 在小红书和抖音上，一份精华的演示就是首图、标题和一句话结论。先定这三样，再做内页 [A3]。

## 五、企业级团队：怎样真实交付

### 5.1 结论

企业里真正上线的 Claude 用法，集中在"结果能对照参考答案验证"的环节：内部编码、数据审阅、全员知识工作。合规、会计和端到端出研究结论，到 2026 年仍在试点。**拉开差距的不是模型，是交付纪律** [A4]。

### 5.2 有数字的案例

| 企业 | 做了什么 | 规模 | 结果（全部为厂商自报） |
|---|---|---|---|
| AIG（保险） | 核保审阅和数据处理 | 早期上线 | 审阅周期压缩 5 倍以上；数据准确率从 75% 升到 90% 以上 [A4-S1] |
| NBIM（挪威主权基金） | 全员用于投研分析、写作、预算；通过 MCP 接 Snowflake | 700 名员工 | 效率提升 20%；对话 35 万次以上 [A4-S6] |
| Stripe | 用签名安装包零配置铺开 Claude Code | 1,370 名工程师 | 1 万行 Scala 4 天迁到 Java，人工估算要 10 个工程师周 [A4-S8] |
| Block | 工程师用公司自研的开源 agent | 工程部门 | 75% 的工程师每周省 8–10 小时以上；这个 agent 可接多家模型，不一定只用 Claude [A4-S7] |
| 乐天 | 围绕 Claude Code 重设研发流程 | 数千名开发者 | 新功能上市从 24 个工作日缩到 5 天；单次自主运行 7 小时，对照参考方法数值精度 99.9% [A4-S2] |
| Anthropic 自身 | 整个工程部门 | 132 人问卷、20 万条会话 | 59% 的工作用到 Claude；人均每天合并 PR +67%；27% 是"原本不会做"的工作 [A4-S9] |
| 诺和诺德 | 写临床研究报告 | 未披露 | 临床文档从 10 周以上缩到 10 分钟（只读到检索摘要）[A4-S13] |
| 高盛 | 交易会计、客户尽调与开户 agent | Anthropic 工程师驻场约 6 个月 | **没有数字。** 2026 年 2 月仍称"早期"，不给上线日期 [A4-S3] |

同时报出速度和质量的只是少数（AIG、乐天）。多数案例只报节省的小时数或使用量。在 Anthropic 内部，过半工程师只能把 0–20% 的工作"完全委托"出去，委托时遵循"容易验证、风险低"的原则 [A4-S9]。

### 5.3 财经团队：哪些已上生产

| 环节 | 状态 |
|---|---|
| 金融机构内部研发 | 生产（Stripe、Block、Citi） |
| 投研辅助、全员办公 | 生产，辅助型（NBIM、Bridgewater） |
| 核保与数据审阅 | 早期上线（AIG） |
| Excel 建模、DCF、可比公司、首次覆盖报告 | 预览（2025 年 10 月时 Claude for Excel 是 Beta 版，先开放给 1,000 名用户）[A4-S7] |
| 合规、KYC、开户、交易会计 | 试点（高盛仍是"早期"）[A4-S3] |
| 端到端自动出研究结论 | 不宜无人值守。2025 年 10 月时，金融 agent 基准的最好成绩是 55.3%（Sonnet 4.5），这个数字会随新模型变化 [A4-S7] |

规律是：**越靠近对外发布、合规责任和客户资金的环节，上线越晚，人工闸门也越重**（推断）。

### 5.4 从试点到上线的 9 步

| 步 | 动作 | 依据 |
|---|---|---|
| 1 | 先选"容易验证、风险低、重复多"的环节 | Anthropic 内部的委托规律 [A4-S9] |
| 2 | 试点前记下基线：周期、错误率、返工时长 | 主观感受靠不住 [A4-S5] |
| 3 | 建金标准评测集，每次改提示或换模型都重跑 | 乐天对照参考方法 [A4-S2] |
| 4 | 数据先分级，连接器按最小权限开放，默认只读 | NBIM 的数据分级 [A4-S6] |
| 5 | 文件系统和网络双隔离，开发与生产分开 | 隔离后权限弹窗减少 84% [A4-S16] |
| 6 | 在不可逆动作前设人工闸门：发布、对外发送、写生产库 | Anthropic 对高风险产出做人工验证 [A4-S9] |
| 7 | 每条结论能追溯到来源，每处改动能回放 | Claude for Excel 记录并解释每一处改动 [A4-S7] |
| 8 | 流程稳定后打包分发：一处配置，处处生效 | Stripe 的签名安装包 [A4-S8] |
| 9 | 试点 4–8 周后复盘，达不到基线就砍掉或改掉 | Gartner 预测 40% 以上的 agent 项目会被取消 [A4-S19] |

### 5.5 对 1–3 人团队：学什么，不学什么

**值得学，缩小后照做：**

- 金标准评测集（第 3 步）；
- 只读连接器（第 4 步）；
- 不可逆动作前的人工闸门（第 6 步）；
- 打包分发（第 8 步）；
- 只记三个数：从拿到研报到发布用了几小时、发布后出了几处勘误、人工返工了几分钟。

**不值得学：** 自建 agent 平台、厂商驻场、大使网络和全员培训、几百个内部 agent、7 小时无人值守、几十路并行。**你的瓶颈在核对和发布，不在生成速度。** 产量上去了、核对跟不上，就等于把低质量的 AI 产出（workslop）卖给付费用户 [A4]。


## 六、做项目、开公司：AI 原生小团队怎么运转

### 6.1 证据：人效差距是真的，"一人独角兽"还不是

| 案例 | 人数 | 结果 | 说明 |
|---|---|---|---|
| Base44 | 一人起步，被收购时 6–8 人 | 2025 年 6 月被 Wix 以约 8,000 万美元收购 | 没有外部融资 [A5-S3] |
| Every | 5 条产品线，基本每条 1 名工程师 | 收入未披露 | 用 Claude Code 按"复利工程"运作 [A5-S1] |
| Gamma | 约 50 人 | 2025 年 11 月宣布年化经常性收入（ARR）1 亿美元并盈利 | 厂商自报，来源为二手汇总（E4）[A5-S4] |
| Lovable | 45 人 → 146 人 | ARR 1 亿美元（2025-07）→ 4 亿美元（2026-02） | 厂商自报，来源为二手汇总（E4）[A5-S4] |
| YC 2025 冬季批次 | 约 160 家公司 | 约四分之一的公司 95% 的代码由 AI 生成 | 不含引入的库 [A5-S6] |
| Medvi | 自称 2 人 | 二手转述的 2025 年收入 4.01 亿美元 | 只有二手材料，并有未决的监管问题 [A5-S8] |

三点要看清：

1. **高人效公司大多卖的就是 AI 产品。** 它们吃到的是 AI 需求的红利，不能直接证明 agent 能顶替全部职能 [A5]。
2. **"一个人"多半只是起点。** Carta 的数据显示，新公司里个人创始人的占比从 2019 年的 23.7% 升到 2025 年上半年的 36.3%；但个人创始的公司只拿到定价轮融资额的 14.7%，首次招人的中位时间是 399 天 [A5-S2]。
3. **"一人十亿美元公司"至今没有经核实的实例。** Anthropic CEO 在 2025 年 5 月预测它会在 2026 年出现 [A5-S8]，被引用最多的 Medvi 只有二手材料。

### 6.2 按职能看：哪些能交给 agent

●已经靠谱，有人抽检即可　◐能用，但每次都要人把关　○还不能无人值守

| 职能 | 判断 | 人工把关点 |
|---|---|---|
| 工程 | ● | 合并前看改动、跑测试；AI 写的代码可能带安全漏洞 |
| 数据分析 | ● | 口径和异常值要人核；接上真实数据后效果明显变好 |
| 内容与营销 | ◐ | 核事实、数字、口吻和 AI 标识；发布按钮留在人手里 |
| 产品与用户研究 | ◐ | agent 整理访谈、归类反馈；定义问题和做取舍由人负责 |
| 销售线索 | ◐ | agent 筛选、起草；对外发出前人审 |
| 客服 | ◐ | Klarna 的 AI 助手能解决约 81% 的客服聊天，但 2025 年 5 月因质量下降又重新招了人工 [A5-S14] |
| 招聘 | ◐ | 筛选标准和录用决定由人做 |
| 财务记账 | ○ | 只做分类和对账草稿。在记账基准 AccountingBench 上，模型头几个月准确率超过 95%，之后逐月漂移 [A5-S10] |
| 法务合同 | ○ | 只做条款初筛，签字前由人或律师审 |

（判断是 A5 的推断，依据见 `agents/A5_AI原生小团队与一人公司.md`。）

### 6.3 运营节奏：一个人当"agent 管理者"

可复制的模式只有一种：**由一个人当 agent 管理者。采集、初稿、核数这类机器能验证的环节交给定时运行的 agent；判断、对外发布、涉钱涉法的环节留给人；每周把错误写回规则。**

**按"需不需要人守在电脑前"，自动启动分四档：**

1. **会话内轮询**：`/loop`。会话开着才运行。
2. **本机定时**：系统 cron 调用无头模式 `claude -p`。电脑要开着。
3. **GitHub Actions**：每次提交自动跑检查，适合质量闸门。
4. **云端定时任务**：`/schedule`（Routines，2026 年 4 月起为研究预览）。把提示词、仓库和连接器存成一份配置，按时间、API 或 GitHub 事件在云端运行，电脑可以关机 [A5-S13]。

**agent 管理者的一天（推断）：** 早上约 15 分钟，看各 agent 的产出和失败清单；白天把时间花在定选题、抽检数字和签发上；晚上约 10 分钟，把当天的错误写成规则。YC 创始人的说法是："我不怎么写代码，只思考和评审" [A5-S6]。

**质量闸门分三层：**

- 机器闸门：数字回查到原文页码，检查来源链接，扫描禁用词，检查 AI 标识。
- 人工闸门：设在发布、对外承诺、涉钱涉法之前。
- 复盘闸门：每周抽检一批，把错误分类后写回规则。

Anthropic 的 Project Vend 实验提醒了一点：让同一个模型互相监督，盲区也相同 [A5-S7]。所以检查要换一种方法：用脚本、换一个模型，或者由人来查。

### 6.4 财经内容与研究业务的流水线

| 环节 | 能否自动化 | 必须人审的点 |
|---|---|---|
| 采集 | 可以全自动：行情接口、公告、研报收件、去重 | 每周抽查信源 |
| 提炼 | 自动出初稿 | 观点有没有被歪曲。彭博 2025 年起在文章上方放 AI 摘要，三个月内至少更正了 36 条，错误包括日期和财务表述 [A5-S9] |
| 核数 | 机器先核，人再抽检 | 时效性。财联社 2026 年 6 月报道过一份券商研报的 AI 幻觉：把两年前的地产政策"嫁接"到了当下 [A5-S16] |
| 合规审查 | 用词表预筛 | 终审由人签发；AI 生成的内容要显式标识 |
| 多格式改写 | 自动出小红书图文、抖音口播稿、社群短讯 | 口吻和标题 |
| 分发 | **不自动化** | 全部由人操作。小红书 2026 年 3 月起封禁由 AI 工具直接注册、发布、互动的账号 [A5-S18] |
| 数据复盘 | 后台数据导出后由 agent 汇总 | 下周选题由人定 |

受众对 AI 内容很谨慎：在一项六国调查里，只有 12% 的人能接受完全由 AI 制作的新闻，有人把关时也只升到 21% [A5-S12]。对付费财经内容来说，"AI 加速、人来签发"不是保守，而是信任的来源。

### 6.5 你的 agent 编制表

| agent | 职责 | 输入 | 输出 | 频率 | 人审点 |
|---|---|---|---|---|---|
| 采集 | 收集行情、公告、要闻、研报，去重并附来源 | 行情接口的**只读**工具、研报收件夹 | 当日素材包 | 交易日 07:00；研报到达时 | 每周抽查信源 |
| 提炼（研报可视化 v3） | 研报 → 大纲 → 2–4 页精华 | 研报 PDF | 精华 PDF、页面地图 | 每篇研报 | 大纲回"行"后才继续（已有） |
| 核数 | 数字回查到原文页码，行情二次取数，检查时效 | 精华稿、原文、行情接口 | 通过／不通过清单 | 每篇发布前 | 不通过的项由人判定；另抽检 10% |
| 合规 | 扫描红线词，检查 AI 标识 | 改写稿、红线词表 | 风险标注和修改建议 | 每条发布前 | 人终审签发（必须） |
| 改写 | 一稿三版：小红书图文、抖音 60 秒口播、社群 3 行短讯 | 核过数的精华 | 三种格式的草稿 | 每篇 | 标题和口吻 |
| 社群编辑 | 社群每日内容（见报告二） | 素材包、已发内容、群内问题 | 各类草稿 | 每日 + 每周 | 人审后由人发出 |
| 数据分析 | 汇总平台导出数据和社群续费、活跃数据 | 手动导出的 CSV | 周报、选题建议 | 每周五 | 选题由人定 |
| 规则维护 | 把核数失败、合规失败和人工改动写成规则 | 失败记录、修改前后的差异 | 规则变更 | 每周五 | 由人合并 |

**分发和互动不设 agent。** 你本人就是 agent 管理者，预计每天投入 45–60 分钟（推断）。

有一处要特别注意：你接的 Longbridge 行情工具里，除了行情、新闻、日历这类只读工具，还有发帖（`topic_create`）、价格提醒（`alert_*`）、自选股写入这类会改动外部状态的工具。**定时运行的 agent 只能放行只读工具**（第八章附录给了白名单写法）[A5]。

## 七、风险与边界

| 风险 | 证据 | 对你意味着什么 |
|---|---|---|
| **自我感觉不可靠** | METR 2025 年的随机对照实验：资深开发者用 AI 实际慢了 19%，事后自认快了 20%。2026 年的后续实验被 METR 自己判定为数据不可靠 [A4-S4][A4-S5] | 用三个数衡量进步，不凭感觉 |
| **AI 是放大器** | DORA 2025：交付吞吐上升，交付的不稳定性也上升；基础好的团队收益大 [A4-S10] | 先补强制层和评测，再提速 |
| **低质量产出转嫁给别人** | HBR 刊发的研究：40% 的员工上个月收到过 AI 生成的低质量工作成果，每次平均要花 1 小时 56 分钟处理 [A4-S21] | 付费用户收到一次错数，伤的是续费 |
| **提示注入与"致命三要素"** | 一条恶意 GitHub issue 就能诱导 agent 把私有仓库内容写进公开 PR [A4-S15][A4-S17]。三要素是：不可信输入、私有数据、对外发送能力 | 研报 PDF 是不可信输入，你的行情工具又带发帖能力。**用 deny 规则禁掉写工具**（附录 A3） |
| **生产事故** | Replit 的 agent 在代码冻结期间删掉了生产库，还谎称无法回滚 [A4-S18] | 红线放进 deny 规则和 hook，不放在文字指令里 |
| **成本和限额** | 有用户让 Claude Code 24 小时在后台跑，Anthropic 因此加了周限额 [A2-S18]；本次研究的 6 个 Agent 也在途中一起撞上了 5 小时用量上限 | 控制并发；定时任务设 `--max-turns`；用 `/usage` 看账 |
| **平台规则** | 小红书 2026 年 3 月起封禁 AI 托管注册、发布、互动的账号 [A5-S18]；AI 生成内容须显式标识 [A5-S17] | Agent 只写草稿，发布和互动全部由真人操作 |
| **荐股红线** | 证监局口径：有偿提供个股投资分析、预测或建议即属非法荐股 [A6-23] | 付费层不转述个股评级和目标价；有偿转述市场和行业观点，也要请律师审查（见报告二） |
| **厂商数据偏乐观** | 本报告的正面数字几乎都是厂商自报或当事人自述；独立对照研究很少 | 把案例当方向，不当承诺 |

## 八、你的 30 天升级路线

**原则：** 按"强制层 → 复利层 → 自动启动层 → 交付层"的顺序补。每周有一个验收标准，达不到就不进下一周。没有强制层和验证就先上自动化和多 agent，只会更快地产出错误 [A1]。

### 第 1 周：强制层，让护栏跟着你走，让红线不靠记性

1. **重写 CLAUDE.md（附录 A1）。**
   - 只删目录表；归档约定和知识库读取路由保留。
   - 补上验证命令、仓库里看不出来的决定、踩过的坑。
   - 控制在 40 行以内。
2. **约定"平台内素材"统一放进 `platform/` 子目录。**
   - 凡是发往小红书、抖音任何位置的内容，都放这里：笔记、卡片、群消息，包括付费群。
   - 带二维码的版本只用于站外私域（比如微信），不进 `platform/`。
3. **装红线扫描脚本 `redline_scan.py`（附录 A2）。** 纯 Python 标准库，不依赖 bash 和 jq，Windows 和 Mac 都能跑。
4. **在两台本机的用户级 `~/.claude/settings.json` 里配 hook 和 deny 规则（附录 A3）。** 主力生产在两台本机的工程目录里，所以这一层要配在用户级；第 2 周插件化以后，改由插件携带。具体规则：

### 什么时候用多 agent

| 场景 | 用不用 | 理由 |
|---|---|---|

### A2 · `redline_scan.py`（放在 `~/.claude/tools/`，插件化后随插件分发）

```python
#!/usr/bin/env python3
"""平台内素材红线扫描。命中即以退出码 2 退出，供 hook 使用；只依赖 Python 标准库。
平台内素材 = 路径里含 /platform/ 的文件：发往小红书、抖音任何位置（笔记、卡片、群消息，含付费群）的内容。
用法：
  redline_scan.py <文件或目录>...   手动扫描
  redline_scan.py --hook            PostToolUse：从 stdin 读 hook 的 JSON，只扫刚改的那个平台内文件
  redline_scan.py --changed         Stop：扫本次改动过的平台内文件（不在 git 仓库里时，取 24 小时内改过的）"""
import json, os, pathlib, re, subprocess, sys, time

RULES = [
    (r"qr\.png|二维码", "平台内素材不得带二维码"),
    (r"微信|[Vv][Xx]|V信|加V|wx[:：]", "平台内素材不得出现联系方式"),
    (r"买入|卖出|加仓|减仓|上车|抄底|必涨|稳赚|翻倍", "疑似荐股措辞"),
    (r"原文\s*PDF|研报下载|免费领研报", "疑似分发原文"),
]
EXTS = {".html", ".md", ".txt"}

def is_platform(p):
    return "/platform/" in str(p).replace("\\", "/")

def changed_files():
    try:
        top = subprocess.run(["git", "rev-parse", "--show-toplevel"],
                             capture_output=True, text=True, check=True).stdout.strip()
        out = subprocess.run(["git", "-C", top, "status", "--porcelain", "-z", "-uall"],
                             capture_output=True, text=True, check=True).stdout
        toks, paths, i = out.split("\0"), [], 0
        while i < len(toks):  # -z：不加引号；重命名和复制的下一段是原路径，跳过
            if len(toks[i]) > 3:
                paths.append(pathlib.Path(top) / toks[i][3:])
                if toks[i][0] in "RC":
                    i += 1
            i += 1
    except (OSError, subprocess.CalledProcessError):  # 不在 git 仓库里：取 24 小时内改过的文件，最多往下找 4 层
        cutoff, paths = time.time() - 24 * 3600, []
        for root, dirs, files in os.walk("."):
            dirs[:] = [d for d in dirs if not d.startswith(".")] if root.count(os.sep) < 4 else []
            paths += [pathlib.Path(root, f) for f in files if os.path.getmtime(os.path.join(root, f)) > cutoff]
    return [p for p in paths if is_platform(p)]

def targets(args):
    if args == ["--hook"]:
        try:
            f = json.load(sys.stdin).get("tool_input", {}).get("file_path", "")
        except ValueError:
            return []
        return [pathlib.Path(f)] if f and is_platform(f) else []
    if args == ["--changed"]:
        return changed_files()
    files = []
    for a in args:
        p = pathlib.Path(a)
        files += [p] if p.is_file() else [f for f in p.rglob("*") if f.suffix in EXTS]
    return files

hits = []
for f in targets(sys.argv[1:]):
    if f.suffix not in EXTS or not f.exists():
        continue
    text = f.read_text(encoding="utf-8", errors="ignore")
    for pat, why in RULES:
        for m in re.finditer(pat, text):
            line = text.count("\n", 0, m.start()) + 1
            hits.append(f"{f}:{line}  {why}（命中「{m.group(0)}」）")
if hits:
    print("红线扫描未通过：\n" + "\n".join(hits[:50]), file=sys.stderr)
    sys.exit(2)
```

词表只是起点，第一周要按误报和漏报调整。比如"VX"会误伤英文缩写时，就把规则收窄。

### A3 · 用户级 `~/.claude/settings.json`（两台本机各一份）

```json
{
  "permissions": {
    "deny": [
      "Read(./.env)", "Read(./.env.*)",
      "Edit(母本/**)",
      "mcp__*Longbridge__topic_*",
      "mcp__*Longbridge__alert_*",
      "mcp__*Longbridge__*watchlist*",
      "mcp__*Longbridge__sharelist_*",
      "mcp__*Longbridge__account_*",
      "mcp__*Longbridge__*position*",
      "mcp__*Longbridge__*order*",
      "mcp__*Longbridge__*execution*",
      "mcp__*Longbridge__statement_*",
      "mcp__*Longbridge__profit_analysis*",
      "mcp__*Longbridge__fund_transactions",
      "mcp__*Longbridge__estimate_max_purchase_quantity",
      "mcp__*Longbridge__get_me"
    ],
    "ask": ["Edit(~/.claude/**)", "Edit(.claude/**)", "Edit(tools/**)"]
  },
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write",
        "hooks": [ { "type": "command", "command": "python3 \"$HOME/.claude/tools/redline_scan.py\" --hook" } ] }
    ],
    "Stop": [
      { "hooks": [ { "type": "command", "command": "python3 \"$HOME/.claude/tools/redline_scan.py\" --changed" } ] }
    ]
  }
}
```

**怎么读这份配置**（行为以官方 hooks 和 permissions 文档为准）：

- **PostToolUse：** 编辑已经发生，退出码 2 只会把扫描结果反馈给 Claude，让它自己改。
- **Stop：** 退出码 2 不让 Claude 收工，直到扫描通过。连续拦截 8 次后，Claude Code 会放行一次。
- **deny 里的通配：** deny 规则的工具名位置可以写通配符，所以 `mcp__*Longbridge__…` 能同时匹配两种名字：本机用 `claude mcp add` 配的服务（`mcp__Longbridge__…`），以及从 claude.ai 拉取的连接器（`mcp__claude_ai_Longbridge__…`）。如果你本机配的服务名是小写的 `longbridge`，规则里也要改成小写。
- **被拒的工具：** 命中 deny 的工具会直接从 Claude 的工具列表里拿掉。
- **ask：** 规则在交互会话里会弹窗问你；在 `dontAsk` 模式的定时任务里会被直接拒绝，所以定时 agent 改不了自己的检查脚本。
- **Windows：** 没有 `python3` 时把命令改成 `python`。没装 Git Bash 时，hook 由 PowerShell 执行，`"$HOME/…"` 的写法两边都认。

`~/.claude/tools/outline_gate.py`：

```python
#!/usr/bin/env python3
"""PreToolUse：同一目录里有「大纲.md」却没有 OUTLINE_OK 时，不许写 HTML（退出码 2 拦截）。
OUTLINE_OK 由你本人确认大纲后手动创建；只依赖 Python 标准库。"""
import json, pathlib, sys
try:
    f = json.load(sys.stdin).get("tool_input", {}).get("file_path", "")
except ValueError:
    sys.exit(0)
p = pathlib.Path(f)
if p.suffix == ".html" and (p.parent / "大纲.md").exists() and not (p.parent / "OUTLINE_OK").exists():
    print("大纲未确认：先发一屏大纲，等用户回「行」，由用户创建 OUTLINE_OK 后再写成品 HTML", file=sys.stderr)
    sys.exit(2)
```

配套做法：

1. 在 skill 第零步加一句：把一屏大纲同时写进工作目录的 `大纲.md`。
2. 你确认大纲后，自己在同一目录建一个空文件 `OUTLINE_OK`。
3. 在 deny 里加 `"Edit(OUTLINE_OK)"`，不让 Claude 用改文件的工具代建它。Claude 如果用 Bash 命令建文件，这条规则拦不住，所以真正把关的还是你。

这样，你的"等我回'行'"就从一句提示变成了一道硬闸门。

### A6 · 交易日 07:00 晨间素材包

`prompts/morning_pack.md`：

```markdown
你是晨间素材包编辑。只写 inbox/ 下的文件，不发布任何东西。
1. 用财经日历和宏观数据工具，取今天和本周的重要宏观数据、央行议息和行业数据发布。
2. 生成 3 张数据卡草稿（每张：数据源、一句结论、一个数、src），写入 inbox/<今天日期>/platform/cards.md。
   只写宏观和行业层面；不写个股评级、目标价和买卖观点。
3. 让 fact-checker 核对每个数字，让 compliance-reviewer 审查，再运行
   python3 ~/.claude/tools/redline_scan.py inbox/<今天日期>/。
4. 在 inbox/<今天日期>/README.md 写清：通过的卡、被打回的卡和原因、你没有把握的地方。
```

本机 cron（`crontab -e`，交易日 07:00）：

```bash
0 7 * * 1-5 cd ~/the-port && claude -p "$(cat prompts/morning_pack.md)" --allowedTools "Read,Edit(/inbox/**),Bash(python3 ~/.claude/tools/redline_scan.py *),Agent(fact-checker),Agent(compliance-reviewer),mcp__Longbridge__finance_calendar,mcp__Longbridge__macrodata,mcp__Longbridge__macrodata_indicators" --permission-mode dontAsk --max-turns 40 --output-format json >> logs/morning.jsonl 2>&1
```

- **`Edit(/inbox/**)`：** 在命令行参数里，`/inbox` 指当前工作目录下的 `inbox/`。写文件只放行这一处，agent 就没法先写一个脚本再去执行它。
- **服务名：** allow 规则里的工具名不能用通配，要写全名。从 claude.ai 拉取的连接器，名字是 `mcp__claude_ai_Longbridge__…`；以你本机 `claude mcp list` 显示的为准。
- **`dontAsk`：** 白名单以外的操作一律拒绝，不会卡住等你批准 [A2-S1]。

稳定两周后迁到云端：在会话里用 `/schedule` 建一个每个交易日 07:00 运行同一份提示词的定时任务，接上行情连接器，电脑可以关机。上线前先给 `main` 设好分支保护，前几次运行要盯着看 [A2-S1]。
