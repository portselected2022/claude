# A3 · 黑客松：高手和强队怎样用 Claude，哪些做法能迁移到真实交付

> 编制：A3 · 2026-11-18
> 检索：WebSearch 14 次，WebFetch 10 次（其中 2 次因 gradio.app 不在网络白名单而失败）。另用 gh 查过 GitHub 仓库元数据（star 数、建仓日期），没有经 gh 读正文。gradio.app、huggingface.co、devpost、luma 和国内媒体站点都读不到原文，相关内容只有检索摘要（E3）。厂商自报、作者自述和推断都在正文里标出。

## 1. 一句话结论

2025–2026 年 Claude 主题黑客松的赢家多是领域专家而不是职业程序员，他们靠"把领域知识写进 skill、先写规格、按模块并行、用小评测和真跑的演示验收"取胜；这套骨架可以压成小团队的每周流程，但熬夜冲刺、预置的演示数据和只够演示用的安全措施不能带进生产。

## 2. 关键发现

1. **领域专家赢，会不会写代码不是门槛。** Anthropic 和 Cerebral Valley 合办的 Opus 4.6 场入选 500 人（第三方称约 13,000 人申请）。5 位获奖者里 4 位不是职业开发者，冠军是一名人身伤害律师，自称"一行代码没写"[S1][S10]。Opus 4.7 场前三名分别是医生、自学电子维修的创业者和大学讲师，第三方称申请人数超过 20,000[S2][S11]。
2. **评委先看演示。** 4.6 场的规则副本显示，第一轮由 6 位 Anthropic 评委按统一标准异步打分，Demo 占 30%，排第一项[S12]（E3）。获奖项目解决的都是能用金额和时长量化的痛点：加州建房许可首次提交被打回的比例超过 90%，平均拖 6 个月；道路可行性研究按传统做法要 100–400 万美元、9–14 个月[S1]。
3. **规格先行是共性。** Maieutic 写代码前先用 2 天写设计和技术规格；ARIA 第 2 天整天在 GitHub 看板上排计划；Wrench Board 先用 Claude Design 出原型，再写规格和分领域的计划[S2]。CrossBeam 的 Agent SDK 计划写了 1,077 行，部署计划 756 行，计划常交给另一个 agent 复审[S4]。
4. **并行按"所有权"切分。** Medkit 同时开 4 个 Claude Code 会话，分别负责语音引擎、内容生成、3D 层和核心应用；Wrench Board 同时跑 5–6 个 agent，一个领域一个[S2]。CrossBeam 的 subagent 出过"过度研究、互相踩踏、上下文爆掉"的问题，后来限定每个 subagent 的范围、各写各的输出文件、由主 agent 读文件汇总，才稳定下来[S4]。
5. **补知识文件、做小评测，比反复改提示有效。** MaestrIA 把 17 条诊断规则、19 个基准价格等内容写进一个知识 JSON。在 12 个真实案例、9 个维度的评测上（标准答案由他做木匠的父亲给出），准确率从 74% 升到 81%，系统提示一字未改[S2]。CrossBeam 第一天就把州政府的 ADU 手册拆成 27 个参考文件，再加一个做决策树路由的 SKILL.md[S4]。
6. **验证做得密，成本也算得清。** Elisa 用 6 天、30 小时完成 76 次提交，写了 39,000 多行代码和 1,500 多个测试[S1]。Medkit 的评分 agent 只能引用一份策展过的临床指南清单，作者的说法是"防止评分编造来源"[S7]。CrossBeam 每次云端运行花 1.46–8.69 美元；为了速度，作者放弃了准确率 95%、耗时 35 分钟的提取方案，改用准确率约 85%、耗时 10–15 分钟的方案[S4]。
7. **转成产品的案例有，但要几个月，而且是少数。** CrossBeam 赛后约半年拿到 Laguna Beach 的 12 个月协议（2026-08-04 一致通过），10 月在 Buena Park 上线免费预检[S3]（作者自述）。Medkit 有 3 所医学院和 1 家药企准备试点；ARIA 的架构将并入其中一位作者的工业物联网平台[S2]。学术上的基线：约 1/3 的黑客松项目赛后还有后续开发，只有约 5% 能持续 5 个月以上（2020 年的研究，E3）[S22]。
8. **赛前准备本身会变成资产。** Anthropic 和 Forum Ventures 合办的纽约场冠军，把自己的 Claude Code 配置（模块化规则、9 个 subagent、hooks、skills）开源为 ECC，截至 2026-11-18 有 306,313 个 star[S8][S9]。Elisa 的作者把赛中的教训整理成 5 个可移植的 skill[S6]。

### 2.3 金融类和内容类的例子

- 没有找到 Claude 主题黑客松里获奖的财经研究或财经内容项目。按项目描述归类，4.7 场的 6 个获奖项目里没有金融类[S2]。
- 最接近的是 TARA：它输出包含 NPV、现金流和敏感性分析的投资评估 PDF[S1]。lablab.ai 的一场 Bright Data 黑客松里有一个参赛项目 MarketPulse AI，为股票分析师做财报前情报，用多 agent 实现；名次和是否用了 Claude 都没说明[S29]。开源项目 cc-equity-research 用 24 个 skill（9 个出自 Anthropic，15 个来自社区）加 1 个数据 MCP 做股票研究，但它不是黑客松的产物[S30]（E4）。
- 内容类：Virtual Puppet 的演示视频是用 Claude 做的，作者提醒"做一个 3 分钟视频比你想的要久得多"[S2]；CrossBeam 按"故事先行、边做边拍"的办法准备视频[S4]。PostVisit.ai（4.6 季军，作者是心内科医生）把病历翻成患者能懂的话，由医生把关[S1]，这和"把专业研报翻成大众能读的中文"是同一种结构（推断）。
- 国内：第一财经报道，小红书黑客松巅峰赛 60% 以上的入围者是 00 后，有选手说"以前组队要前端、后端、运维，现在一个人基本就能完成"[S24]（E3）。新华网转载的报道引述 Dr.Job 的估算：全球每年举办的 AI 黑客松从 2024 年约 2,800 场增至 2026 年预计 4,200 场[S23]（E3）。

## 3. 可以直接照做的做法

| 做法 | 动作 / 配置 | 依据 | 适用条件 |
|---|---|---|---|
| 赛前备好脚手架 | 仓库级 CLAUDE.md，加上按主题拆分的规则文件（安全、测试、git）；几个限定工具范围的 subagent（计划、评审、安全审查）；每次编辑后自动格式化和类型检查的 hook | ECC 作者（纽约场冠军）公开的配置[S8] | 同类任务每周重复 2 次以上 |
| 精简工具 | 每个项目只开当前要用的 MCP：开着的少于 10 个，工具总数少于 80 个 | 工具过多时，200k 的上下文"可能只剩 70k"可用[S8] | 接了多个 MCP 或插件 |
| 把领域知识写进 skill | 参考文件按主题拆分，SKILL.md 只做决策树路由；规则和基准值写成结构化文件注入 | CrossBeam 第 1 天建好 27 个参考文件[S4]；MaestrIA 准确率提高 7 个百分点[S2] | 有稳定的规则、术语或基准 |
| 规格先行，再请人复审 | 动手前写一页规格：目标、非目标、接口、失败模式；计划交另一个 agent 审；按"计划、审计、修补、对齐、编码"多轮推进 | Maieutic 用 2 天写规格，ARIA 用 1 天排计划[S2]；coherence 里的边界定义和多轮计划两个 skill[S6] | 任务超过半天，或涉及多个文件 |
| 从演示倒推范围 | 先定要讲的故事和必须真跑的那条主路径，其余功能标"即将推出"；输出质量优先于界面 | CrossBeam 只接一个城市，砍掉 PDF 生成，"agent 输出质量 > 漂亮的 UI"[S4] | 有固定的交付时点 |
| 按所有权并行 | 一个会话或 agent 只负责一个模块或文件夹；subagent 各写各的输出文件，由主 agent 读文件汇总；同时跑 3–6 路 | Medkit 4 个会话，Wrench Board 5–6 个 agent[S2]；CrossBeam 用文件协调[S4] | 任务能拆成互不修改同一文件的几块 |
| 时间盒，量化取舍 | 难点设截止时间，到点就换方案；把"准确率、耗时、单次成本"列成表再选 | CrossBeam 下午 4:15 转向"先读懂更正项，再去找相关图纸"；95%/35 分钟对比 85%/10–15 分钟[S4] | 有两个以上可行方案 |
| 评测和输出契约 | 用 10–12 个真实案例多维打分，标准答案由专家给，每次改知识或提示后重跑；agent 之间传递的输出用固定格式，并加版本号；引用只能来自白名单 | MaestrIA 从 74% 升到 81%[S2]；CrossBeam 因输出是嵌套结构、解析器要的是平铺数组而丢了数据[S4]；Medkit 的指南白名单[S7] | 产出要对外发布，出错代价高 |
| 真跑验证，尽早部署 | 发布前在干净环境里把真实流程跑一遍；先上线能用的版本，再打磨 | CrossBeam 的评委演示事故和 office hours 给的建议[S4] | 所有对外交付 |
| 长会话及时重置 | 会话太长，或同一个问题反复修不好时，停下来写一页书面简报，再开新会话 | coherence 里的手动压缩重置和协作检查点两个 skill[S6] | 单个会话持续数小时（推断） |

**评委看重什么。** 公开的权重只有"Demo 30%"一项[S12]。从奖项设置（Keep Thinking、最具创意、最佳 Managed Agents）和获奖者的背景看，评委奖励三件事：真实且能量化的痛点，能真跑的端到端闭环，以及对新能力（视觉、Managed Agents、多 agent）的实质使用（推断）。CrossBeam 在 office hours 得到的建议是"部署优先于打磨"[S4]。

## 4. 反例、失败与局限

1. **演示不等于系统。** CrossBeam 给评委的演示回放的是预先算好的结果，根本没有运行 agent。作者在提交前 45 分钟才发现，用 12 分钟、8 次提交补上了真跑模式[S4]。Demo 占 30% 的评分规则，容易诱导"做给评委看"[S12]。
2. **冲刺的节奏不能复制。** CrossBeam 最后约 30 小时里只睡了 6 小时，视频凌晨 2:51 才导出[S4]。这是一周一次的极限状态，不是每周能重复的节奏。
3. **并行会互相踩踏。** 多个 subagent 会过度研究、互相覆盖、把上下文撑爆[S4]。一支拿了第二名的队伍要规定"一个会话只负责一个文件或文件夹"，才不再冲突[S21]（E4）。
4. **测试和数据只够演示。** CrossBeam 的日志里只有冒烟测试和模拟会话数据，既没有系统地拿真实更正函比对，也没有做幻觉评测，而且只预置了一个城市的数据[S4]。Medkit 声明"病例是合成的，不做临床声明"，多 agent 交接和用户账户都不在范围内[S7]。
5. **安全、发布和许可常被跳过。** Elisa 的安装包"尚未做代码签名"[S5]；Medkit 写着"私有，不得再分发"，仓库却是公开的[S7]。在 10 个项目的公开描述里，只有 MaestrIA 写明做了防提示注入和限流[S2]。
6. **转化慢，比例低。** CrossBeam 的仓库自称"黑客松快照，不是当前产品"[S3]，从比赛结束到拿到第一份市政协议花了约 6 个月（据日期推断）。只有约 5% 的黑客松项目能持续 5 个月以上[S22]。国内也有批评：部分 AI 黑客松把开发时间压到一个下午，有的项目只交 PPT[S25]（E4）。

## 5. 对委托人的启示

1. **把研报可视化 skill 改成"路由加参考文件"的结构。** 照 CrossBeam 的做法：SKILL.md 只留流程闸门和路由，把各家投行的版式差异、常用图表、术语译法和合规红线拆成参考文件，用到时再加载。字体、二维码和构建脚本收进一个共享目录，不再每个项目复制一份（现在各有 22 份）。适用条件：每周做 3 份以上研报。
2. **建一个 12 份研报的"金标准"评测集。** 照 MaestrIA 的做法：从已经发布的精华版里挑 12 份，人工定 8–9 个打分维度，例如数字能否回溯到原文、有没有荐股措辞、是否有 AI 标识、页数是否合规、每页是否只有一个主角、术语译法、时效、有没有原文段落。每次改 skill 或换模型后重跑一遍，记下分数。这比"感觉好多了"可靠，也是他目前没有测试和 CI 时成本最低的补丁。
3. **把黑客松那一周压成每周的固定循环。** 周一花 30 分钟写一页周规格（选题、不做什么、交付物、红线检查项），交给另一个会话复审。周二到周四按"一份研报、一个会话、一个文件夹"并行 2–3 路，主会话只做汇总和终审。发布前用 Stop hook 自动跑现有的 PDF 机器回查和覆盖报数脚本。周五写一页决策日志（类似 CrossBeam 的 progress.md），同时更新知识文件和评测分数。
4. **他的"演示"是首图和前 3 秒。** 黑客松里 Demo 占 30%，强队都是"故事先行、边做边拍"。在小红书和抖音上，一份精华版的演示就是首图、标题和一句话结论。先把这三样定下来，再做内页；短视频版本单独留一个时间盒（推断）。
5. **有三样不要迁移：熬夜冲刺、预置的演示数据、只够演示的合规。** "不荐股、不发原文、AI 内容要标识"这三条要写进 hook 或检查脚本，变成硬规则。行情 MCP 只在需要数据的会话里打开。每份产出都记下耗时和花费，再据此决定下一步自动化什么。
