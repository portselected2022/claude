# 研究框架与分工（主协调维护）

> 编制日期：2026-11-18。本文件是所有 Agent 的共同底稿：委托人画像、证据标准、预算、交付格式、分工与轮次。

## 一、委托人画像（仅内部使用；检索词里不得出现任何个人信息）

- **业务**：财经内容创作者（小团队），品牌 THE PORT · 港口精选，把高盛、大摩、摩根大通、美银等投行研报做成中文提炼型可视化精华。主战场是小红书和抖音。付费产品为年卡 399 元/年（含开放群聊）、月卡、专题合集。
- **红线（已定）**：不荐股、不发原文、平台内不留微信、不用 AI 托管账号自动发布和互动、AI 生成内容要显式标识。
- **Claude 使用现状**（主协调核对过仓库）：
  - 已自建 2 个 skill：「研报可视化 v3」（有流程闸门、页面地图、PDF 机器回查和覆盖报数脚本）和「金融数据 reader」；接入了 Longbridge 行情 MCP；做过飞书知识库机器人；做过一次 12 个 Agent、多轮的研究项目，产出约 46 万字的报告。
  - 没有 hooks，没有自定义 subagent，没有测试和 CI，没有定时或无人值守任务。每个产出放在一次性文件夹里，构建脚本、字体和二维码按项目复制（二维码和字体各复制了 22 份）。仓库提交集中在少数几天，说明使用方式是"有活时集中对话"。
- **自评**："用 Claude Code vibe coding 了，感觉还是停留在小白初学者阶段，没有很大的提升。"
- **他要的答案**：
  1. 现在大家用 agent / 多 agent 做自动化，主要在解决哪些方向的问题、提升哪些效率；
  2. 程序员和成熟财经团队（不限于财经）做项目、开公司时，怎样把 Claude 用到最大；
  3. 黑客松里的高手和企业级团队，怎样高效使用 Claude 并真实交付有价值的结果；
  4. 结合 399 元年卡社群：在多 Agent 每日协助下，还能加什么内容来提高付费可能性。前提一：用户天然反感广告，一扫而过是常态；前提二：用户不接受长文字，越短越好。

## 二、时间与证据标准

- 今天是 2026-11-18。优先使用 2025-01-01 以后的资料，每条来源写明发布日期。2025 年以前的资料只在概念源头时引用，并注明年份。
- 证据等级：
  - **E1**：一手原文已读（官方博客、文档、论文、财报、公司公告），并用 WebFetch 读过原文。
  - **E2**：可信二手原文已读（主流媒体、知名从业者的长文）。
  - **E3**：只看到检索摘要，未读原文。
  - **E4**：个人自述、社媒帖子、营销材料。
- 厂商自报的数据（Anthropic 和其客户案例）可以引用，但要标"厂商自报"。
- 推断一律标"（推断）"。不编造；找不到就写"未找到"。

## 三、预算与纪律

- 每个 Agent：WebSearch 不超过 14 次，WebFetch 不超过 10 次。并行 Agent 共享检索配额，超额会被系统打断（10-19 那轮研究就被打断过）。
- 先写文件骨架，边查边写，避免中断后丢稿。
- 检索词里不放委托人的品牌、姓名或任何个人信息。

## 四、交付格式（每个 Agent 交一份备忘录）

路径：`agents/Axx_主题.md`。中文，正文 3,000–4,500 汉字（不含来源表）。结构如下：

1. 一句话结论
2. 关键发现：5–10 条，每条写"事实 + 数字 + [来源编号]"
3. 可以直接照做的做法：具体到动作、配置或流程，并写明适用条件
4. 反例、失败与局限：至少 3 条
5. 对委托人的启示：3–5 条，具体到他的业务
6. 来源表：编号 | 标题 | 作者/机构 | 日期 | URL | 证据等级

## 五、分工

| Agent | 主题 | 核心问题 |
|---|---|---|
| A1 | 用途地图 | 大家用 agent / 多 agent 主要解决什么问题；用途在 2025→2026 年怎么变；多 agent 什么时候有用、什么时候反而坏事 |
| A2 | 高手工作流与进阶阶梯 | 公认高手的真实工作流；新手和高手的可观测差别；L0–L5 进阶阶梯；反模式；可抄的配置 |
| A3 | 黑客松 | 2025–2026 年以 Claude / Agent 为主的黑客松：谁赢了、怎么做的；哪些做法能迁移到真实交付，哪些不能 |
| A4 | 企业级团队交付 | 金融和非金融企业的案例与量化结果；组织方式与治理；反面证据；从试点到上线的交付打法 |
| A5 | AI 原生小团队与一人公司 | 小团队和一人公司用 agent 跑全职能的证据；日常与每周的自动化循环；对财经内容和研究类业务的流水线 |
| A6 | 付费社群转化 | 在"反感广告、只看短文"的前提下，免费转付费的证据和机制；多 Agent 每日协助能生产的内容；合规边界 |
| A7（R3） | 反方审查 | 审查两份报告初稿：过度推断、证据不足、数字核验、对委托人不适用之处 |

## 六、轮次

- **R1**：A1–A6 并行取证，各交一份备忘录。
- **R2**：主协调整合，起草《报告一：深度反馈》和《报告二：社群付费内容方案》。
- **R3**：A7 做反方审查，核验关键数字。
- **R4**：主协调裁决、定稿、提交。
